# Codexが使えない時の代役（Claudeのエージェント2体）

2026-10-02 運営者の判断。Codexは利用制限でちょくちょく止まる（2026-10-02の昼過ぎに上限→復帰は10/4 2:47）。
止まった間は「Codexの検証なしで公開」になり、2AIで確かめる仕組みが抜けていた。
**Codexが使えない時は、Claudeのエージェントを2体立てて、Codexの代わりにする。**

対象: wansakansai-spot-update-am / -pm（STEP 7・7.5）、wansakansai-danger-update（STEP 5.8・5.9）。
この手順は2026-10-02に、読む役・崩す役のエージェント2体で点検してから入れた（指摘は全部反映済み）。

## いつ代役に切り替えるか

Codexを呼んだら、毎回その出力ファイルを点検する:

```bash
python scripts/codex_limit_check.py （codex exec の出力ファイル）
```

| 終了コード | 意味 | やること |
|---|---|---|
| 0 | 最終の答えが返った（`tokens used` の後ろに答えがある） | いつもどおり突き合わせへ |
| **20** | **利用制限**（usage limit・quota exceeded・429） | **代役に切り替える** |
| 1 | 最終の答えが無い（空・接続エラー・`No prompt provided` などで途中で終わった） | 1回だけ呼び直す。それでも1なら代役に切り替える |

ほかに代役に切り替えるのは、`codex --version` が失敗した時（未インストール）と、20分待っても判定が1件も出なかった時。

**理由を問わず、一度代役に切り替えたら、この実行の残り（2巡目・修正レビュー）もすべて代役で行い、Codexを呼び直さない。**
（タイムアウトの日に修正レビューだけCodexへ戻すと、待ち時間がさらに20分増え、判断の担い手も途中で入れ替わる）

切り替えたらログに1行書く:
`[codex-standin] 開始 理由=（利用制限／答えなし／タイムアウト／未インストール） （codex_limit_check.py の出力行）`

### 20分で一部だけ判定が出ていた時

出た分はそのまま使う。**判定が出なかった対象だけ**で、生成スクリプトの `--ids` を付けてプロンプトを作り直し、それを代役に渡す
（元のプロンプトを渡すと、Codexが判定済みの分まで調べ直して時間を倍使う）。代役に渡すのは**多くて3件**。それより多い分は
検証済みにせず、翌日以降の追いかけ検証（`pending_codex_catchup.py`）に回す。

## 立て方

### 1. 指示文をスクリプトで作る（手書きしない）

```bash
python scripts/build_standin_prompt.py --role a --prompt-file （Codexに渡すはずだったプロンプト） --out （出力先A）
python scripts/build_standin_prompt.py --role b --prompt-file （同じもの） --out （出力先B）
```

- Instagram の素材（`insta_{ID}_{DATE}/` の画像・profile.txt）を取っていたら、両方に `--material （パス）` を付ける（複数可）
- 出力先はプロンプトと同じフォルダに `_standin_a.md` / `_standin_b.md` を付けた名前でよい
- **手書きしない理由**: 修正内容を知っている本体が書くと、「とくに〇〇の料金を」のような一言が混ざり、2体の独立が崩れる
- 指示文には、2体が守ること（一次情報の原文で確かめる・ほかのローカルファイルを開かない・Chromeを使わない・「反証なし」は「確認できず」・時間の目安・全件に答える・ファイルを書かない）がもう入っている

### 2. 2体を同時に立てる

**Agent ツールで general-purpose を2体、同じメッセージの中で同時に立てる**（`run_in_background` は false）。
- prompt には、作った指示文ファイルの**中身をそのまま**貼る（足さない・削らない。本体の判断やもう一方の答えを書き加えない）
- 役目は A＝**読む役**（一次情報で項目ごとに確かめる）、B＝**崩す役**（もう違っている根拠を探す）。
  同じことを2回させると同じ見落としを2回する（2026-09-28の犬の可否点検で効いたやり方）

### 3. 片方だけ答えなかった時

エラー・途中で切れた・一部の対象が答えに無い（「未着手」を含む）時は、**その役だけ1回立て直す**（答えの無い対象だけで
プロンプトを作り直してよい）。それでも答えが無い対象は、**1体だけの答えで検証済みにしない**。
その対象は `[codex-skip] 代役が片方しか答えず` として扱う（追いかけ検証が拾う）。

### 時間の上限

1体あたり**20分**が目安（指示文にも「1件4分・全体20分、終わらない分は未着手」と書いてある）。
1回のタスクで代役を立てるのは、1巡目1回＋修正レビュー（最大3巡）まで。Claude側の利用量も食うので、これ以上増やさない。

## 2体の答えのまとめ方

2体の答えを、**Codex1体の答えの代わり**として扱う。対象（項目）ごとに:

| A | B | Codexの答えとしてどう扱うか |
|---|---|---|
| 同じ判定・同じ値 | 同じ判定・同じ値 | その判定（いつもの突き合わせ表へ） |
| 判定あり | 確認できず | 判定ありの側（片方が裏を取れなかっただけ）。ただし「問題なし／一致／支持」を1体だけが言っている時は、その根拠URLを本体が開いて原文を確かめてから採る |
| 確認できず | 確認できず | 「確認できず」 |
| 要修正（値X） | 要修正（値Y） | **「割れ」**（直すべきという点は一致しても、正しい値が割れている） |
| **違う判定** | **違う判定** | **「割れ」** |
| 答えあり | 答えなし | 上の「片方だけ答えなかった時」へ。立て直しても無ければ、その対象は検証済みにしない |

- 「割れ」はいつもの「結論が割れた場合」の手順（公式を自分で開いて決着 → 決着しなければ変更しない＋人へ）
- 本体の判断との突き合わせ・決着のしかた・タグ（`[codex-resolved]` `[codex-diff]` など）は**Codexの時とまったく同じ**。
  ただしどの行にも代役だと分かる印を付ける: `[codex] （代役） …` のように書く
- **「エージェントが言っているから」を根拠にしない**。Codexの時と同じく、指摘は自分で開いて確かめてから採る。
  とくに「公式にこう書いてある」という引用は、**生のページで実在を確かめる**（2026-09-28にエージェントが出した「公式の原文」が実在しなかった）

### 2巡目以降（危険情報の2巡目・修正レビューの2巡目と3巡目）

- 毎回**新しく2体を立てる**（前の巡のエージェントを使い回さない）。指示文は同じスクリプトで、その巡のプロンプトから作る
  - 危険情報の2巡目のプロンプトは `build_codex_danger_prompt.py --round 2 --ids … --diffs "…"`
  - 修正レビューの2巡目以降のプロンプトは `build_codex_change_review_prompt.py --round 2 --prior （前巡の答えのJSON）`
- 修正レビューで「支持」とするのは、**2体とも支持（または片方が支持・片方が確認できず）**の時。どちらかが不支持なら不支持として往復する
- **2巡目以降の不支持は、前の巡で争った点に限って数える**。新しい崩す役が別の論点を持ち出した時は、それを本体が自分で開いて確かめ、
  正しければ採り、根拠が無ければ「確認できず」に読み替える（毎巡新しい論点で不支持が出ると、正しい修正まで3巡で捨てられるため）
- **不支持には「違う内容が書かれたURLと原文」が要る**。それが無い不支持は「確認できず」に読み替える
- 止め時はいつもどおり（一致するまで・3巡で揃わなければ公開せず人へ）

## 記録とメール

- 検証できたIDは、Codexの時と同じく `[codex-verified]` に並べてよい（代役で検証済み）。ただし**行末に `（代役）` だけを付ける**。
  `claude-agent-a` などの語はこの行に書かない（追いかけ検証のスクリプトがIDとして拾う）
- 判断者を書く欄（コミットメッセージなど）では `claude-agent-a,claude-agent-b` と書く。**「codex」と書かない**
- **代役だけを理由にメールは送らない**（「静かなのが正常」）。ほかの理由で送るメールには
  `send_notify.py` に `--note "Codexが利用制限のため、Claudeのエージェント2体で検証した（N件）"` を付ける
- 代役でも結論が割れて決着しなかった項目（`[codex-diff]` `[codex-change-diff]`）は、いつもどおりメールで人に渡す。
  `--note` に「Codexが利用制限のため、Claudeのエージェント2体で判断した」と書く
- 代役が何日続いているかは、ログの `[codex-standin]` を数えれば分かる（watchdog などで見る時の手がかり）

## 代役も使えなかった時だけ

Agent ツールがエラーになる等で2体とも答えが得られなかった時だけ、従来の扱いに戻る:
機械チェックを通った内容で確定し、`[codex-skip] 理由（Codex制限＋代役も失敗）` を記録してメールに明記する。
タスクは止めない（止めると「黙って止まる」を自分で作る）。この日のぶんは翌日以降の追いかけ検証（`pending_codex_catchup.py`）が拾う。
